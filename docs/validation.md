# 验证与部署

## 自动化验证

兼容基线：OpenClaw 2026.11.2、SnowLuma 服务端2.3.4。开发测试使用Node26.13.0，也验证过Bun1.4.4运行时的SQLite与真实消息链路。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm check
pnpm exec vp check
node scripts/smoke-host.mjs
pnpm pack
```

当前151项自动化测试覆盖结构化流式协议、会话与账号边界、SQLite迁移、入站合批、出站节奏、持久用户名、图片引用、附件准备和真实本地WebSocket/HTTP传输。类型检查、构建和格式/lint检查通过；macOS及原生Linux x86_64均验证过。`scripts/smoke-host.mjs`使用临时状态和配置，调用真实OpenClaw宿主检查插件加载、通道和工具注册，不启动QQ连接。

## Docker接入示例

在SnowLuma容器内启用WS服务端：监听0.0.0.0:3001、路径 `/`、数组消息格式，并设置Access Token。若OpenClaw运行在Docker宿主机，可将端口只发布到回环地址：

```yaml
ports:
  - "127.0.0.1:13001:3001"
```

此时插件连接 `ws://127.0.0.1:13001/`。令牌通过环境变量或仅当前用户可读的文件提供；两端必须匹配。合并[通用配置](../examples/openclaw.json)时保留现有插件名单、agent和路由，只追加本插件及rion绑定。

插件固定只连接rion。创建独立工作区并配置 `agents.entries.rion`，把qq-snowluma绑定至rion；回退到main、其他agent或无来源出站将被拒绝。人格模板可从 `examples/rion/` 复制到该工作区。

## 真实客户端验收

请只在自己明确授权的群或私聊中测试：

1. 账号校验、群目录与有界历史读取，确认发送者、群名片、时间和引用。
2. 流式分句、引用/@的独立选择、静默结果，以及首轮10秒安静等待与30秒封顶。
3. 图片、语音、视频、文件、转发节点与引用内媒体；查看图片时确认多模态附件或短引用读取路径。
4. 拍一拍、原生表情和表情回应；检查动作后面的文字也发送。
5. 临时缩短测试会话的idleAfterMs，验证只尝试一次开场；结束后恢复原值。
6. 断线重连、进程重启、未读补齐、用户命名持久化和自身消息不循环。

已在真实部署验证文本、引用、表情回应、常规PNG、文件发送及真人@触发rion回复；也验证过真实GIF短引用还原与附件保存。语音、视频、主动开场等未逐项完成真实客户端验收，自动化测试不替代这些观察。

API成功表示提供方接受请求，不证明接收设备已显示或已读；图片上传成功不等于模型识别准确。发送结果不确定时保留回执等待核对，不自动重放。

## 已知兼容边界

宿主的media-runtime公共兼容入口会产生弃用信息，在2026.11.2上仍可使用。其他OpenClaw版本需独立验证；插件不声明未来宿主版本兼容性。
